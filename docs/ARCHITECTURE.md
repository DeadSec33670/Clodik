# Архитектура ArhoShop

## Обзор

```
                    ┌─────────────────────────────┐
   Браузер / PWA ──►│  Node-сервер (server/)      │
                    │  • статика: site/ app/ data/ │
                    │  • REST API: /api/*          │
                    └───────────┬─────────────────┘
                                │
        ┌───────────────────────┼─────────────────────────┐
        ▼                       ▼                           ▼
   node:sqlite            integrations/              loyalty/validate
   (users, orders,        email · payment ·          (бизнес-правила
    product_views)        catalog-sync                ТЗ — единый код)
```

Бэкенд намеренно **без внешних зависимостей**: `node:http` (роутер), `node:sqlite` (БД),
`node:crypto` (scrypt-хэш паролей + HMAC-подписанные токены). Это убирает шаг `npm install`,
снижает поверхность атак и ускоряет старт.

## Модель данных (ТЗ §6/§7)

- **User**: `id, name, phone (uniq), email (uniq), password_hash, spent, bonuses, created_at`.
- **Loyalty**: хранится в `users.spent`/`users.bonuses`; `tier` **вычисляется** из `spent`
  (`lib/loyalty.js`) — не денормализуется.
- **Order**: `id (номер A#####), user_id|null, items_json, total, delivery, city, status,
  earned_bonuses, created_at`. Гостевые заказы — `user_id = NULL`.
- **Product**: каталог отдаётся статикой (`site/data/*`), популярность — `product_views`.

## Ключевые бизнес-правила (реализованы и покрыты тестами)

1. **Уникальность**: один телефон = один аккаунт, одна почта = один аккаунт (UNIQUE + проверки).
2. **Валидация**: телефон → 11 цифр (8/9 → 7), email по формату, пароль ≥ 6.
3. **Вход** только для существующего аккаунта; неверный пароль → ошибка.
4. **Заказ** требует имя/телефон/город и выбранный размер у каждой позиции.
5. **Лояльность**: `earned = floor(total × rate(tier(spent_до_покупки)))` — кэшбэк
   по уровню **на момент покупки**; затем `spent += total`, `bonuses += earned`.
   1 бонус = 1 ₽. Уровни: Бронза 50k/1%, Серебро 100k/2%, Золото 250k/3.5%, Платина 500k/5%.
6. **Популярность**: «Популярное сейчас» ранжируется по числу просмотров (счётчик кликов).
7. **Нижнее бельё** относится к «Одежде» и показывается последним (нормализация на витрине).

## Безопасность

- Пароли: `scrypt` с индивидуальной солью, сравнение `timingSafeEqual`.
- Токены: компактный самоподписанный (HMAC-SHA256) с TTL — как JWT, без библиотек.
- Серверная пересборка суммы заказа из позиций (защита от подмены `total`).
- `forgot` отвечает одинаково независимо от существования email (анти-энумерация).
- Лимит тела запроса 1 МБ; защита статики от выхода за корень.

## Фронтенд

- **Сайт** (`site/index.html`): исходный прототип сохранён целиком; заменён лишь слой данных
  — `api.js` (клиент API) + ленивая подгрузка каталога. Аккаунт/заказы/лояльность идут в API.
- **Приложение** (`app/index.html`): рантайм-прототип (`support.js`), методы auth/checkout
  подключены к тому же API; добавлена PWA-оболочка (manifest + service worker).
- Оба используют общий `api.js` (`ArhoAuth`, `ArhoCatalog`, `ArhoPopular`).
